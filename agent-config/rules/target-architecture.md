# Target Architecture Rules (.NET 8+)

Applies to all code generated by `target-modernizer` in Phase 5. Self-review against
this list before handing off to `test-verifier`.

## Runtime & project structure
- SDK-style `.csproj`, targeting `net8.0` (or later LTS as directed).
- `Program.cs` minimal hosting model — no `Startup.cs`/`Global.asax` split unless the
  team has explicitly requested the older `Startup.cs` pattern.
- `PackageReference` for all dependencies — no `packages.config`.

## Configuration
- All configuration through `appsettings.json` + `appsettings.{Environment}.json`,
  bound via `IOptions<T>`. No hardcoded connection strings, URLs, or secrets in code.
- Secrets never committed — use user-secrets/environment variables/a secret manager,
  referenced but not embedded in `appsettings.json`.

## Dependency injection & lifetime
- All services registered via `Microsoft.Extensions.DependencyInjection` in
  `Program.cs`. No `new ServiceX()` inside controllers or business logic.
- Correct lifetimes: `DbContext` scoped, stateless services singleton or scoped as
  appropriate — never inject a scoped service into a singleton without justification.

## Data access
- Entity Framework Core 8, `DbContext`-based. No direct `SqlConnection`/ADO.NET unless
  `plan.md` explicitly calls for it (e.g., a legacy stored procedure with no
  clean EF Core equivalent).
- Async data access throughout (`ToListAsync`, `SaveChangesAsync`, etc.).

## Web layer
- ASP.NET Core Web API controllers or Razor Pages/MVC, per the approach confirmed at
  HITL Gate 2. If a decoupled SPA was chosen, the API layer must not embed
  presentation logic.
- No `HttpContext.Current` — inject `IHttpContextAccessor` where request context is
  genuinely required.
- No in-proc `Session` reliance carried over uncritically — if the legacy module relied
  on in-proc session/session affinity, flag it in Phase 1/4 and use a distributed
  approach (e.g., Redis-backed cache) in the target.

## Cross-cutting
- Logging via `Microsoft.Extensions.Logging` (structured logging via Serilog if the
  team requires it).
- `System.Text.Json` by default; `Newtonsoft.Json` only if a specific serialization
  behavior genuinely requires it, and note why.
- Nullable reference types enabled (`<Nullable>enable</Nullable>`).
- Async/await for all I/O-bound code — no blocking `.Result`/`.Wait()`.

## Testing
- xUnit for all generated tests, FluentAssertions/Moq as needed.
- Business logic must be unit-testable without spinning up the full web host (no
  static state, constructor-injected dependencies).
